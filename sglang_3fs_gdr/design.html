1. 概述与背景

1.1 问题定义

SGLang 推理框架通过 3FS 分布式文件系统进行 KV Cache 的存储和加载。当前数据传输路径存在额外的 CPU 内存拷贝：

现有路径 (3FS USRBIO): GPU 显存 ──cudaMemcpy──▶ CPU 共享内存 (Iov) ──RDMA──▶ 3FS 存储节点 SSD ▲ 额外的 PCIe DMA 拷贝 GDR 优化路径: GPU 显存 ───────────RDMA (GPUDirect)─────────▶ 3FS 存储节点 SSD ▲ 零拷贝: 跳过 CPU 内存

1.2 GPUDirect RDMA (GDR) 简介

GPUDirect RDMA 是 NVIDIA 的技术，允许 RDMA NIC 直接访问 GPU 设备内存，无需经过主机 CPU 内存中转。通过 nvidia-peermem 内核模块，IB/RoCE NIC 可以直接对 GPU 显存执行 DMA 传输。

特性传统 RDMA (CPU 内存)GPUDirect RDMA (GPU 显存)
数据路径GPU → CPU → NIC → 网络GPU → NIC → 网络
拷贝次数2 次 (GPU↔CPU + CPU↔NIC)0 次 (直接 DMA)
延迟~10-50 μs (依赖 PCIe)~2-5 μs
CPU 开销高 (需要 memcpy)零 (不经过 CPU)
依赖标准 RDMAnvidia-peermem + MOFED

1.3 3FS 现有 RDMA 架构

3FS (Fire-Flyer File System) 是 DeepSeek 开源的高性能分布式文件系统，采用 RDMA-First 架构：

  • 使用 C++ ibverbs 封装 (IBSocket) 实现 One-sided RDMA
  • 存储节点通过 RDMA Write 将数据写入客户端内存
  • USRBIO API：基于共享内存的零拷贝 I/O 接口
  • 当前缓冲区为 CPU 共享内存 (Iov)，尚未支持 GPU 显存
核心思路： 扩展 3FS 的 USRBIO Iov 机制，将缓冲区从 CPU 共享内存替换为 GPU 设备内存，通过 GDR 实现 GPU↔3FS 的零拷贝传输。

3. 模块详细设计

3.1 GDR 核心层 gdr_core

3.1.1 GDRDetector — GDR 能力检测

负责检测系统是否满足 GPUDirect RDMA 运行条件：

  • nvidia-peermem 内核模块加载状态 (通过 /proc/modules)
  • NVIDIA GPU 设备与 RDMA NIC 的 P2P 可达性 (nvidia-smi topo -m)
  • IB 端口状态 (/sys/class/infiniband/)
  • CUDA GDR 属性 (CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED = 106)
# 检测流程
detector = GDRDetector()
report = detector.detect()

#     "ib_devices": ["mlx5_0", "mlx5_1"],

3.1.2 GPUMemoryManager — GPU 内存与 RDMA 注册

管理可用于 GDR 的 GPU 设备内存分配和 RDMA 注册：

# 核心流程
1. cuMemAlloc_v2()    → 分配 GPU 设备内存
2. cuMemGetAddressRange() → 获取 GPU 物理地址
3. ibv_reg_mr()       → 注册 GPU 内存到 RDMA Protection Domain
4. 返回 GDRBuffer {gpu_ptr, gpu_addr, mr_lkey, mr_rkey}

# 内存池管理
mgr = GPUMemoryManager(gpu_id=0, ib_dev="mlx5_0", pool_size_gb=4)
buf = mgr.alloc_buffer(1024 * 1024 * 1024)  # 1GB from pool

关键 MR 访问标志：

  • IBV_ACCESS_LOCAL_WRITE — 本地写入
  • IBV_ACCESS_REMOTE_READ — 远程 RDMA Read
  • IBV_ACCESS_REMOTE_WRITE — 远程 RDMA Write
  • IBV_ACCESS_RELAXED_ORDERING — 宽松排序 (提升性能)

3.1.3 RDMAOps / RDMATransport — RDMA 操作

封装基于 GPU 内存的 RDMA verbs 操作：

  • rdma_write() — RDMA Write (one-sided)：本地 GPU → 远端内存
  • rdma_read() — RDMA Read (one-sided)：远端内存 → 本地 GPU
  • post_recv() — 投递接收请求 (two-sided)
  • batch_write() — 批量 RDMA Write (一次 post 多个 WR)
  • poll_completion() — 轮询 CQ 获取完成事件
# RDMA Write with GPU memory
result = transport.rdma_write(
    local_buf=gdr_buf,       # GPU 显存缓冲区
    remote_addr=0x7f000000,  # 远端 GPU 内存地址
    rkey=0x1234,             # 远端 MR 的 rkey
    length=4096,
)
# 全程不经过 CPU 主机内存

3.2 3FS GDR 桥接层 hf3fs_bridge

3.2.1 UsrbioGDRExtension — USRBIO GDR 扩展

扩展 3FS 的 USRBIO API，增加 GPU 显存作为 Iov 缓冲区：

组件原始 3FSGDR 扩展
Iov (数据缓冲区)CPU 共享内存 (mmap)GPU 设备内存 (cuMemAlloc + ibv_reg_mr)
Ior (控制环形)CPU 共享内存不变 (控制面数据量极小)
RDMA 传输NIC ↔ CPU 内存NIC ↔ GPU 显存 (GDR)
# Iov 头部结构 (4096 bytes)
[0:8]   magic          = 0x4846334653000000
[8:16]  version         = 2 (GDR version)
[16:24] capacity        = pool_size
[24:32] gpu_ptr          = GPU 虚拟地址
[32:40] gpu_phys_addr    = GPU 物理地址
[40:44] lkey             = RDMA Local Key
[44:48] rkey             = RDMA Remote Key
[48:56] mr_handle        = ibv_mr 句柄
[56:64] ib_dev_name      = "mlx5_0"

# 3FS USRBIO daemon 读取头部获取 GPU MR 信息
# 然后执行 RDMA Write 到 GPU 显存

3FS 存储节点的 USRBIO daemon 读取 Iov 头部后，获取 GPU 内存的 rkey 和 gpu_addr，然后执行 ibv_post_send(IBV_WR_RDMA_WRITE) 将 SSD 数据直接写入 GPU 显存。

3.2.2 HF3FSGDRClient — 3FS GDR 高层客户端

提供 SGLang 使用的 3FS 高层接口：

  • read_to_gpu() — 从 3FS 读取数据直接到 GPU 显存 (GDR 优先, FUSE 回退)
  • write_from_gpu() — 从 GPU 显存写入 3FS
  • load_kv_cache() — 异步加载 KV Cache 到 GPU tensor
  • store_kv_cache() — 异步存储 KV Cache 到 3FS
  • load_model_weights() — 通过 GDR 加载模型权重

回退机制：当 GDR 不可用时自动回退到 FUSE 路径 (CPU 中转)。

3.3 HiCache GDR 后端 hicache

3.3.1 GDRStorageBackend — HiCache 存储后端

实现 SGLang HiCache 的 StorageBackend 接口：

# SGLang HiCache 三级缓存架构
L1: GPU VRAM (热数据)     ← 直接 GPU 计算
L2: Host DRAM (温数据)    ← CUDA memcpy
L3: GDRStorageBackend     ← RDMA 零拷贝 (本方案)
    └─ 3FS distributed storage

# 接口实现
def get(key) → Optional[bytes]           # 从 3FS 读取
async def get_to_gpu(key, tensor) → bool  # GDR 零拷贝读取到 GPU
def set(key, value) → bool               # 写入 3FS
async def set_from_gpu(key, tensor) → bool # GDR 零拷贝写入
def exists(key) → bool
def prefetch(key)                          # 异步预取

3.3.2 GDRIOBackend — HiCache I/O 后端

管理 GDR 传输的 I/O 调度策略：

  • 同步 GDR (gdr)：提交后立即等待完成
  • 异步批量 GDR (gdr_async)：批量提交多个请求，一次轮询
  • I/O 深度控制：限制并发 GDR 传输数量
  • 批量提交：聚合请求减少协议开销
  • 预取支持：提前通过 GDR 预取下一段数据

3.4 通信层 GDR 适配 comm

3.4.1 GDRRelayBackend — SGLang Relay 后端

实现 SGLang 的 relay 后端接口，用于跨阶段 GPU 数据传输：

# SGLang omni relay 后端对比
MooncakeRelay:  GPU → Mooncake → CPU → RDMA → CPU → GPU
GDRRelayBackend: GPU → RDMA → GPU (完全绕过 CPU)

# 接口实现
async def put_async(data_ref) → bool       # 发送 GPU 数据
async def get_async(data_ref) → GDRBuffer  # 接收 GPU 数据
async def batch_get(data_refs) → list      # 批量接收

3.4.2 GDRTransportRouter — 传输路由扩展

在 SGLang 的传输路由逻辑中增加 GDR 选项：

# 传输选择逻辑
if same_node:
    transport = CUDA_IPC (GPU) or SHM (CPU)
else:  # 跨节点
    if gdr_available and cuda_tensor:
        transport = GDR           ← 优先 GDR
    elif gdr_available and via_3fs:
        transport = GDR_3FS        ← 通过 3FS 中转
    else:
        transport = MOONCAKE       ← 回退 Mooncake

4. 数据流设计

4.1 KV Cache 加载流 (GDR 路径)

1
SGLang 调度器检测 KV Cache miss，调用 GDRStorageBackend.get_to_gpu()
2
HF3FSGDRClient 分配 GPU 缓冲区 (GPUMemoryManager.alloc_buffer())
3
UsrbioGDRExtension 提交 GDR 读请求到 Ior 环形缓冲区
4
3FS USRBIO daemon 读取 Iov 头部，获取 GPU MR 信息 (rkey + gpu_addr)
5
3FS 存储节点从 SSD 读取数据，执行 ibv_post_send(IBV_WR_RDMA_WRITE) 到 GPU 显存
6
NIC 通过 GDR 直接 DMA 到 GPU 显存 (nvidia-peermem 模块处理地址映射)
7
UsrbioGDRExtension.wait_completion() 轮询 Ior 完成区获取状态
8
SGLang 调度器从 GPU 显存直接使用 KV Cache (零拷贝)

4.2 KV Cache 存储流 (GDR 路径)

1
SGLang HiCache L2 淘汰，调用 GDRStorageBackend.set_from_gpu()
2
HF3FSGDRClient.store_kv_cache() 提交 GDR 写请求
3
3FS 存储节点执行 ibv_post_send(IBV_WR_RDMA_READ) 从 GPU 显存读取数据
4
3FS 存储节点将数据写入 SSD (chunk_engine)
5
写入完成通知通过 Ior 回传客户端

4.3 跨节点 GPU 数据传输流 (GDR Relay)

1
SGLang Pipeline 阶段 A 的 GPU tensor 需要传送到阶段 B (不同节点)
2
GDRTransportRouter 检测到 GDR 可用，选择 GDRTransportType.GDR
3
阶段 A 的 GDRRelayBackend.put_async() 执行 RDMA Write 到阶段 B 的 GPU
4
阶段 B 的 GDRRelayBackend.get_async() 接收 GPU tensor
5
数据直接在 GPU 间传输，不经过 CPU

5.2 核心代码片段

GPU 内存分配与 RDMA 注册

# gdr_core/gpu_memory_manager.py — 核心函数

def _alloc_and_register(self, size: int) -> Optional[GDRBuffer]:
    # 1. 分配 GPU 设备内存
    dptr = ctypes.c_uint64(0)
    self._lib_cuda.cuMemAlloc_v2(ctypes.byref(dptr), size)

    # 2. 获取 GPU 物理地址 (用于 RDMA 定位)
    phys_base = ctypes.c_uint64(0)
    self._lib_cuda.cuMemGetAddressRange(
        ctypes.byref(phys_base), ..., dptr.value
    )

    # 3. 注册 RDMA Memory Region (GPU 内存!)
    mr = self._lib_ibverbs.ibv_reg_mr(
        self._pd,                           # Protection Domain
        ctypes.c_void_p(dptr.value),        # GPU 设备内存指针
        size,                               # 大小
        IBV_ACCESS_LOCAL_WRITE |            # 本地写
        IBV_ACCESS_REMOTE_READ |           # 远程读
        IBV_ACCESS_REMOTE_WRITE |          # 远程写
        IBV_ACCESS_RELAXED_ORDERING,        # 宽松排序
    )
    # nvidia-peermem 模块自动处理 GPU↔NIC 地址映射

    return GDRBuffer(
        gpu_ptr=dptr.value,
        gpu_addr=phys_base.value,
        mr_lkey=mr_lkey,
        mr_rkey=mr_rkey,
    )

USRBIO GDR Iov 头部写入

# hf3fs_bridge/usrbio_gdr.py — Iov 头部写入

def _write_iov_header(self):
    buf = self.mem_mgr._pool[0]  # 第一个 GPU 缓冲区

    header = bytearray(4096)
    struct.pack_into("Q", header, 0, 0x4846334653000000)  # magic
    struct.pack_into("Q", header, 8, 2)                    # GDR version
    struct.pack_into("Q", header, 16, buf.size)            # capacity
    struct.pack_into("Q", header, 24, buf.gpu_ptr)        # GPU 虚拟地址
    struct.pack_into("Q", header, 32, buf.gpu_addr)       # GPU 物理地址
    struct.pack_into("I", header, 40, buf.mr_lkey)        # RDMA lkey
    struct.pack_into("I", header, 44, buf.mr_rkey)        # RDMA rkey

6. SGLang 集成方案

6.1 启动参数

# SGLang 启动命令 (GDR 模式)
python3 -m sglang.launch_server \
  --model-path /3fs/stage/models/DeepSeek-R1 \
  --tp 8 \
  --host 0.0.0.0 \
  --port 10000 \
  --enable-hierarchical-cache \
  --hicache-ratio 2 \
  --hicache-mem-layout page_first_direct \
  --hicache-io-backend gdr \                    # ← GDR I/O 后端
  --hicache-storage-backend gdr_3fs \            # ← GDR 存储后端
  --hicache-write-policy write_through \
  --hicache-storage-prefetch-policy wait_complete

总结： 本方案通过五层架构 (GDR核心 → 3FS桥接 → HiCache后端 → 通信层 → 工具) 实现了 SGLang 基于 3FS 的 GPUDirect RDMA 支持。核心创新在于扩展 3FS USRBIO 的 Iov 机制，将数据缓冲区从 CPU 共享内存替换为 GPU 设备内存，并通过 ibv_reg_mr 注册为 RDMA 可访问区域，实现 GPU↔3FS 存储的零拷贝传输。同时提供了完整的 GDR 环境检测、回退机制和性能基准测试工具。
